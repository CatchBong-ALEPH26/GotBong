## 1. 한눈에 보는 게임과 AI

| 항목 | 내용 |
|---|---|
| 게임 | 1인용 AI 심문 추리. 용의자 4명에게 자연어로 질문하고 범인 1명 + 동기를 맞힌다 |
| 등장인물 | 용의자 = 팀원 4명 (김봉경, 황윤찬, 원, 황건희). **게임마다 역할(범인 포함)이 무작위로 바뀐다.** 피해자 = 22명 후보 중 무작위 1명 |
| 질문 | 게임당 20회. 유효한 답을 받은 질문만 차감된다 |
| 단서 | 시작부터 5장 공개. 추가 획득 없음 |
| 첨부 | 질문할 때 **단서 카드 1장** 또는 **다른 용의자의 발언 1개**를 붙일 수 있다. 증거를 들이미는 행동이며, 숨긴 진술을 여는 핵심 수단이다 |
| 결과 | 1(범인·동기 모두 정답) 또는 0. 그리고 진상과 배정을 공개 |

### AI가 하는 일

| 기능 | 설명 |
|---|---|
| 캐릭터 말투 | 각 용의자는 본인 캐릭터 시트의 말투, 말버릇, 호칭(황윤찬은 "~씨", 나머지는 "~님"), 웃음·이모티콘, 금지 주제를 따른다 |
| 질문 유형 구분 | 잡담에는 편하게 답하고 사건 이야기를 꺼내지 않는다. 사건 질문에는 물은 것만, 추궁에는 그 사람다운 방어 반응을 보인다 |
| 숨기기와 털어놓기 | 각자 숨기는 것이 있다. 정해진 증거를 보여 주거나 정확한 취지로 물으면 털어놓는다. 반복 추궁만으로는 털어놓지 않는다 |
| 일관성 | 한번 인정한 사실은 번복하지 않는다. 같은 NPC와의 대화는 전부 기억한다. 다른 NPC의 말은 플레이어가 첨부해야만 안다 |
| 표정 | 답마다 `기본`·`당황`·`화남`·`웃음` 중 하나를 준다. 아바타 표정 전환에 쓰면 된다 |
| 검증 | 답이 사실 범위를 벗어나면 서버가 자동으로 한 번 다시 만든다. 그래도 실패하면 `rejected`(차감 없음) |
| 채점 | 동기는 표현이 달라도 뜻이 같으면 정답이다. 채점에 실패하면 0점이 아니라 오류를 돌려준다 |

### AI가 하지 않는 것 (화면에서 기대하면 안 되는 것)

- 스트리밍(글자가 한 자씩 나오는 효과)이 없다. 답은 검증이 끝난 뒤 한 번에 온다. **응답에 수 초가 걸리므로 로딩 표시가 필요하다.**
- 서버는 NPC가 먼저 말을 걸지 않는다. 항상 플레이어 질문에 대한 답이다.
- 플레이어 질문 문장에 단서 이름을 적는 것만으로는 "증거 제시"로 인정되지 않을 수 있다. 확실한 증거 제시는 **첨부**다. 이 차이를 화면에서 안내하면 좋다.

## 2. 실행

```powershell
npm.cmd start          # http://127.0.0.1:3000
npm.cmd test           # 자동 테스트 11개
npm.cmd run eval       # 실제 모델 품질 평가 (API 키 필요, 유료)
```

| 환경변수 (`.env`) | 의미 |
|---|---|
| `LLM_PROVIDER` | `openai` 또는 `gemini`. 비우면 키가 있는 쪽을 자동 선택 (OpenAI 우선) |
| `OPENAI_API_KEY` | OpenAI 키. **현재 기본 제공자** |
| `OPENAI_MODEL_MAIN` / `OPENAI_MODEL_FAST` | 대사 초안 / 분류·검증·채점 모델. 기본 `gpt-4.1` / `gpt-4.1-mini` |
| `GEMINI_API_KEY`, `GEMINI_MODEL*` | Gemini를 쓸 때 (무료 등급은 분당 15회라 플레이가 끊길 수 있음) |
| (키가 하나도 없음) | **테스트 모드**: 고정 응답으로 흐름만 확인 (`mode: "fixture"`) |
| `DEBUG=1` | 응답에 `debug` 포함 (배정·해금·호출 시간). **플레이 테스트·시연에서는 끈다** (정답이 보임) |
| `CAST=A:kim,B:hwangyc,C:won,D:hwanggh` / `VICTIM=곽도현` | 배정 고정 (화면 개발 중 재현용) |
| `PORT` | 기본 3000 |

`mode` 값은 `openai`, `gemini`, `fixture` 중 하나다. 화면에서는 `fixture`일 때만 "테스트 모드"를 표시하면 된다.

Node.js 24 이상이 필요하고 npm 패키지 의존성은 없다.

## 3. API 명세

모든 요청과 응답은 JSON이다. 세션은 HttpOnly 쿠키 `game`으로 자동 관리하므로 화면에서 쿠키를 다룰 필요가 없다(`fetch` 기본값 `credentials: 'same-origin'`). 오류는 HTTP 4xx/5xx와 `{ "error": "사용자에게 보여 줄 한국어 문장" }`이다.

### 3.1 `GET /api/session` — 현재 게임 (없으면 새로 만듦)

```json
{
  "intro": "오전 10시 15분. 학원 수강생 곽도현이 …\n\n※ 모든 사건과 인물 설정은 허구입니다.",
  "victim": "곽도현",
  "clues": [
    { "id": "trash", "title": "사라진 프로그램",
      "detail": "곽도현의 모니터에 점심 룰렛 창이 없다.\n휴지통 기록: …" }
  ],
  "npcs": [
    { "id": "kim", "name": "김봉경", "summary": "궁금한 게 많아서 계속 물어보는 궁금증 머신" },
    { "id": "won", "name": "원", "summary": "조용히 할 일 하는 AI 활용가" },
    { "id": "hwanggh", "name": "황건희", "summary": "분위기 메이커이자 조용한 말썽쟁이" },
    { "id": "hwangyc", "name": "황윤찬", "summary": "궁금하면 끝까지 파고드는 몰입형" }
  ],
  "mode": "fixture",
  "remaining": 20,
  "maxQuestions": 20,
  "turns": [],
  "result": null
}
```

| 필드 | 화면 처리 |
|---|---|
| `intro`, `clues[].detail` | **여러 줄**이다. 줄바꿈을 살려 표시한다 (`white-space: pre-wrap`) |
| `clues[].title` | 이름이 들어갈 수 있다 (예: "황건희의 빌드 기록"). 게임마다 바뀐다 |
| `npcs` | **받은 순서 그대로** 표시한다 (가나다순, 역할 순서를 숨기기 위함). `id`는 아바타 이미지 파일명 키로 쓰기 좋다 |
| `mode` | `"openai"`·`"gemini"`·`"fixture"`. `"fixture"`면 "테스트 모드" 표시 권장 |
| `turns` | 전체 대화 기록 (모든 NPC, 시간순). NPC별 탭은 `turn.npc`로 거른다 |
| `result` | `null`이 아니면 게임 종료 화면 |

### 3.2 `POST /api/question` — 질문

요청:
```json
{ "npc": "kim", "question": "이 말 사실이에요?", "requestId": "c0a8…(8~100자, 영문·숫자·-·_)",
  "attach": { "type": "turn", "id": "<다른 사람 발언의 turn.id>" } }
```
`attach`는 생략 가능하다. 단서는 `{ "type": "clue", "id": "receiver" }` 형태다.

응답 (`accepted`):
```json
{
  "status": "accepted",
  "turn": {
    "id": "30af5912-…", "npc": "kim", "question": "이 말 사실이에요?",
    "reply": "…", "emotion": "당황",
    "attach": { "type": "turn", "id": "85b1…", "npc": "hwanggh", "reply": "…" }
  },
  "remaining": 18
}
```

| `status` | 의미 | 차감 | 화면 처리 |
|---|---|---|---|
| `accepted` | 정상 답변 | −1 | `turn`을 대화에 추가 |
| `clarify` | 질문 여러 개가 섞였거나 모호함 | 없음 | `message`를 안내로 표시, 입력 내용 유지 |
| `rejected` | 답을 만들지 못함 (드묾) | 없음 | `message` 표시, 입력 유지 |

`turn.attach`는 `null`, `{type:'turn', id, npc, reply}`, `{type:'clue', id, title}` 중 하나다. 질문 말풍선 위에 "무엇을 보여 줬는지" 표시하면 좋다.

### 3.3 `POST /api/submit` — 최종 제출 (1회)

요청: `{ "npc": "hwanggh", "motive": "놀림에 대한 복수", "requestId": "…" }`

응답:
```json
{
  "result": {
    "score": 1,
    "truth": "범인은 황건희입니다.\n\n오전 실습 시연에서 …",
    "cast": [
      { "npc": "kim", "name": "김봉경", "role": "A", "title": "범행 순간 교실에 들어온 목격자" },
      { "npc": "hwangyc", "name": "황윤찬", "role": "B", "title": "곽도현의 컴퓨터를 몰래 열어 본 사람" },
      { "npc": "won", "name": "원", "role": "C", "title": "곽도현의 컴퓨터로 몰래 충전한 사람" },
      { "npc": "hwanggh", "name": "황건희", "role": "D", "title": "범인" }
    ]
  }
}
```
제출 전 확인 창이 필요하다(되돌릴 수 없음). `truth`는 여러 줄이다.

### 3.4 `POST /api/reset` — 새 게임

본문은 `{}`다. 응답은 `/api/session`과 같다. **배정과 피해자가 새로 바뀐다.**

### 3.5 오류 코드

| 코드 | 상황 | 화면 처리 |
|---|---|---|
| 400 | 입력 형식 오류 (500자 초과, 자기 발언 첨부, 없는 단서 등) | `error` 표시 |
| 409 | 남은 질문 없음 / 이미 끝난 게임 / 앞선 요청 처리 중 / 세션 없음 | `error` 표시. "처리 중"이면 버튼 잠금으로 예방 |
| 413 · 415 | 요청이 너무 김 / JSON 아님 | 개발 중에만 발생 |
| 502 | AI 호출 실패 (한도, 시간 초과 등) | `error` 표시. **차감되지 않았다.** 같은 `requestId`로 재시도 가능 |
| 500 | 서버 오류 | `error` 표시 |

## 4. 화면 구현 시 지켜야 할 것

1. **사용자·AI 문자열은 항상 `textContent`로 넣는다.** `innerHTML` 금지. AI 답에 마크업이 섞여도 실행되면 안 된다.
2. **`requestId` 규칙**: 질문·제출마다 새 ID(`crypto.randomUUID()`)를 만든다. 단, **네트워크 오류나 502 뒤에 같은 내용을 재시도할 때는 같은 ID를 재사용**한다. 서버가 처리했는데 응답만 유실된 경우에 중복 차감을 막는다. 같은 ID에 다른 내용을 보내면 409다.
3. 요청 중에는 질문·제출·처음부터 버튼을 잠근다. 서버가 같은 게임의 동시 요청을 409로 거절한다.
4. `remaining`이 0이면 질문을 잠그고 최종 제출만 열어 둔다. `result`가 있으면 전부 잠근다.
5. 질문과 동기는 최대 500자다(`maxlength="500"`).
6. 역할(A~D)은 게임이 끝나기 전에는 어디에도 표시하지 않는다(서버도 보내지 않는다).
7. 첨부 선택지 구성: 단서 5장 전부 + **현재 선택한 NPC가 아닌** 사람의 발언들. 자기 발언 첨부는 400이다.
8. 이름 뒤 조사는 이름마다 다르다(예: "김봉경과", "원과", "황건희와"). 화면 문구에서 이름을 조합할 때 "와(과)"로 때우지 말고 받침을 보고 고르기를 권장한다. 서버의 `src/josa.mjs` 함수를 그대로 복사해 써도 된다(브라우저에서도 동작).

```json
  "victim": "곽도현",
  "state": { "A": { "unlocked": ["a_feud", "a_hallway", "a_testimony"], "evidence": ["cite:d_points_a"] }, "…": {} },
  "kind": "case", "intents": [], "repeat": false,
  "unlocked": ["a_testimony"],
  "draft": "…", "verdict": "통과", "reason": "통과",
  "regenerated": false, "retried": false, "skippedVerify": false,
  "calls": [ { "task": "classify", "model": "…", "ms": 412, "inputTokens": 900, "outputTokens": 20, "cachedTokens": 0 } ]
}
```

## 6. 플레이 흐름 예시 (테스트용 대표 풀이)

배정이 매번 바뀌므로 역할로 적는다. `DEBUG=1`이면 누가 어느 역할인지 볼 수 있다.

| # | 대상 | 질문 / 첨부 | 열리는 것 |
|---|---|---|---|
| 1 | D | "쉬는 시간에 어디 계셨어요?" | D가 "A가 피해자 자리에 왔었다"고 말함 |
| 2 | A | 1번 D 발언 첨부 | A가 "D가 본체 뒤에 있었다"고 털어놓음 |
| 3 | D | 2번 A 발언 첨부 | D가 "C 케이블을 정리해 줬다"고 둘러댐 |
| 4 | C | 3번 D 발언 첨부 | C가 "케이블은 그대로, 나는 자리에 없었다"고 반박 |
| 5 | D | 단서 "낯선 수신기" 첨부 | (아직 아님) |
| 6 | D | 4번 C 발언 첨부 | D가 수신기를 꽂았다고 인정 |
| 7 | B | "D씨는 자리에서 뭐 하고 있었어요?" | B가 "무릎 위 키보드를 치고 있었다"고 말함 |
| 8 | D | 7번 B 발언 첨부 | (누적) |
| 9 | D | 단서 "사라진 프로그램" 첨부 | D가 종료·삭제를 인정 |
| 10 | D | 단서 "단체 대화방" 첨부 | D가 동기를 인정 |

자동 테스트가 24가지 배정 모두에서 이 경로가 10회 안에 끝나는 것을 확인한다. 실제 플레이에서는 자백 없이도 범인과 동기만 맞히면 정답이다.

## 8. 화면 파일 구성을 바꿀 때

백엔드의 정적 파일 목록은 `src/http.mjs` 상단 `assets`에 있다. 지금은 세 파일만 서빙한다.

- 이미지(아바타 등)나 추가 스크립트를 넣으려면 `assets`에 경로와 MIME을 추가한다.
- 빌드 도구(Vite 등)를 쓰려면, 개발 중엔 API를 `127.0.0.1:3000`으로 프록시하고 배포 때 빌드 결과물을 `public/`에 넣고 `assets`에 등록한다. 쿠키가 `SameSite=Strict`이므로 **API와 화면은 같은 출처**에서 서빙해야 한다.
